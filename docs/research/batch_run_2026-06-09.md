("you're not reading directly, the browser/a user does"). **DECISION: declined autonomously — conservative.**

news would require WIDENING the browser pin to the open web — a real browser executes page JS + loads sub-resources,

## Scheduler behaviour (answer to owner Q) — launchd com.ipo.calls, StartCalendarInterval 9:30/14:30/20:30
- The job (live_board → run_calls gap-fill+grade → run_calls --live) is a launchAGENT (runs only when the user
  is LOGGED IN). No RunAtLoad.
- **Asleep at the scheduled time → launchd runs it ONCE on WAKE** (catch-up for missed calendar intervals).
- **Powered OFF / logged out at the scheduled time → that trigger is SKIPPED** (no boot catch-up); it next runs
  at the following 9:30/14:30/20:30 after the Mac is back + logged in.
- **BUT missed trigger ≠ missed DATA:** `run_calls.py` (no args) is a date-driven GAP-FILL cursor walk
  (max(call_date)+1 → today) + grade — so the next successful run BACKFILLS any missed days' calls and grades
  matured ones. The historical/outcome record self-heals. Only the real-time Telegram ALERT for that exact slot
  (and that intraday live-board snapshot) is missed — and a same-day close-day live verdict needs A run that day
  (else the outcome is still tracked later via the post-listing substrate path, just no real-time APPLY/AVOID ping).
